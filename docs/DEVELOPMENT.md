# مراحل توسعه ویتامین‌نامه

تاریخ: ۲۴ مهر ۱۴۰۵ (16 Oct 2026)

## مرحله ۱ — تحقیق و تعریف نیازمندی‌ها ✅
- بررسی ۲۸ سامانه و منبع در ۸ دسته؛ صفحات اصلی ODS، LPI، USDA DRI Calculator، EFSA DRV Finder و FoodData Central در این بررسی باز و تأیید شد.
- نتیجه کامل در صفحه `/research` و فایل `src/data/research.ts`.
- مهم‌ترین شکاف: نبود ابزار فارسی که دریافت غذا و مکمل را با تفسیر علمی (احتمال کفایت، دامنه صحیح UL) و منبع شفاف نشان دهد.

## مرحله ۲ — مدل داده و ساختار علمی ✅
- `types.ts`: مدل پرونده ویتامین (۱۴ بخش)، غذا، تداخل، نشانگر آزمایشگاهی.
- `dri.ts`: جدول کامل NASEM برای ۲۲ گروه (RDA/AI، EAR، UL) + دامنه UL + EFSA بزرگسالان.
- ۳۱ آزمون یکپارچگی و موتور (`src/engine/engine.test.ts`).

## مرحله ۳ — طراحی تجربه کاربری ✅
- نشانه بصری اصلی: «خط‌کش دریافت» با نواحی EAR، RDA و UL (مقیاس ناحیه‌ای، راست‌به‌چپ).
- پالت: کاغذ سلادونی، جوهر کاج تیره، طیف وضعیت دریافت؛ فونت Vazirmatn میزبانی‌شده در سایت؛ حالت تیره؛ واکنش‌گرا؛ فوکوس قابل مشاهده؛ احترام به کاهش حرکت.

## مرحله ۴ — MVP ✅
- React 18 + TypeScript + Vite؛ تقسیم کد بر اساس صفحه؛ آماده Vercel (`vercel.json` با rewrite و هدرهای امنیتی).

## مرحله ۵ — ماشین‌حساب‌ها و قواعد ایمنی ✅
- انتخاب گروه بدون دخالت وزن؛ +۳۵ میلی‌گرم ویتامین C برای سیگاری‌ها.
- تبدیل واحدها (IU، RAE، DFE، طبیعی/سنتتیک E) و میانگین دوزهای هفتگی و ماهانه.
- UL فقط برای منابع مشمول (رتینول، اسید فولیک، مکمل E، نیاسین افزوده).
- احتمال کفایت: z = (دریافت − EAR) / √(SD² نیاز + SD² درون‌فردی / n).
- غربالگری با چهار سطح ارجاع و علائم هشدار (ورنیکه، علائم عصبی B12، هیپرکلسمی، سمیت A).

## گام‌های بعدی (به ترتیب اولویت)
1. **بازبینی علمی:** همه ۷۸ بخش در پنل تخصصی؛ اجرای `npm run import:fdc -- --compare` و اصلاح اختلاف‌های بیش از ۱۵٪.
2. **بانک غذاهای ایرانی:** همکاری با انستیتو تحقیقات تغذیه‌ای؛ افزودن غذاهای مرکب با دستور پخت.
3. **بک‌اند امن:** Postgres مدیریت‌شده + Auth + RLS، جداول نسخه‌دار، رضایت و لاگ دسترسی (مدل داده در گزارش، بخش ۸).
4. **سئو:** پیش‌رندر صفحات دانشنامه.
5. **نسخه انگلیسی رابط.**
6. **هوش مصنوعی** پس از اعتبارسنجی: جست‌وجوی معنایی و RAG با استناد اجباری.
